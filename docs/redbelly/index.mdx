<Note>
  **No new contracts.** SODAX's Redbelly spoke contracts are already live; your entire integration is TypeScript. Your users sign ordinary EVM transactions on Redbelly, and SODAX coordinates cross-network execution, routing, and recovery behind the scenes.
</Note>

You keep shipping on Redbelly. SODAX absorbs the cross-network execution layer, so your product can offer trading and lending against every asset in the SODAX System, <span data-sodax-config="count" data-metric="swap-tokens">166</span> across all supported networks, without leaving your stack. Integration happens in TypeScript, at the SDK or React layer. There is nothing to deploy, audit, or maintain on-chain.

Using SODAX is free. Trades carry a fixed 0.1% base fee taken by the protocol, and you set your own platform fee on top. That part is fully yours, both the rate and the revenue. See [Monetize SDK](/developers/how-to/monetize_sdk).

## What to know on Redbelly

To the SDK, Redbelly is a standard EVM network: the same `EvmWalletProvider`, ERC-20 approvals, and intent flow as any other EVM network. Two Redbelly details are yours to know about:

- **Accounts need Redbelly network access.** Redbelly is a permissioned-access network. Before an account can write to it, its owner claims a Redbelly Network Access Credential from an accredited issuer, which verifies a passport with biometric checks, and then enables the account. Creating an intent on Redbelly is a write, so your users need access before they can start a swap or money market action from Redbelly. They set it up through Redbelly's [access dApp](https://access.redbelly.network/).
- **Gas is priced in US dollars.** Redbelly fixes the unit gas price in US dollar terms and charges it in RBNT at the on-chain RBNT price, so the RBNT cost of the same transaction changes with the RBNT price. Redbelly notes that most wallets are not configured for this and may show gas information inaccurately.

## Scope and build with AI

Point your AI coding assistant at the [SODAX Builders MCP](/builders-mcp) and it gains live access to the whole SODAX System: supported chains and tokens, real swap quotes, money market rates, intent history, and these docs. It works in Claude, Cursor, VS Code, Windsurf, and any other MCP-capable client.

```json
{
  "mcpServers": {
    "sodax-builders": {
      "url": "https://builders.sodax.com/mcp"
    }
  }
}
```

Use it to scope before you commit: your assistant can read your own codebase, pull real quotes and token lists, and map exactly where SODAX fits in your product. Full tool list and per-client setup at [builders.sodax.com](https://builders.sodax.com/).
