Fragmented money markets mean lower capital efficiency and worse rates. The SODAX money market pools lending liquidity on the hub while letting users act from any supported network, including Redbelly. A user can supply tokens from Redbelly and borrow on another network, or borrow into their Redbelly account against collateral held elsewhere, without your product running its own lending infrastructure.

Four actions, all through `sodax.moneyMarket`: `supply`, `borrow`, `withdraw`, `repay`. Each has a complete one-call form (handles the relay end-to-end) and a `create*Intent` form when you want the transaction only. Every action sourced on Redbelly is a Redbelly transaction, so the account needs Redbelly network access.

The assets that work in the money market from Redbelly are a subset of the Redbelly swap list, and native RBNT is not among them today. Read the list at runtime, as below, or see [Networks & Assets](/redbelly/networks-and-assets).

## Supply from Redbelly

Supplying an ERC-20 token needs an allowance first, the same as any EVM network:

```typescript
import { Sodax, ChainKeys } from '@sodax/sdk';

const sodax = new Sodax();

// find() returns XToken | undefined, so narrow before using the address
const redbellyTokens = sodax.moneyMarket.getSupportedTokensByChainId(ChainKeys.REDBELLY_MAINNET);
const usdc = redbellyTokens.find(t => t.symbol === 'USDC');
if (!usdc) throw new Error('USDC is not a supported money-market token on Redbelly');

const params = {
  srcChainKey: ChainKeys.REDBELLY_MAINNET,
  srcAddress: await walletProvider.getWalletAddress(),
  token: usdc.address,
  amount: 100n * 10n ** BigInt(usdc.decimals), // 100 USDC
  action: 'supply',
} as const;

const allowance = await sodax.moneyMarket.isAllowanceValid({ params });
if (!allowance.ok) throw allowance.error;
if (!allowance.value) {
  const approval = await sodax.moneyMarket.approve({ params, walletProvider });
  if (!approval.ok) throw approval.error;
  // wait for the approval to be mined before supplying
}

const result = await sodax.moneyMarket.supply({
  params,
  walletProvider, // IEvmWalletProvider, narrowed by srcChainKey
  timeout: 120_000, // optional relay timeout (default 120 s)
});
```

## Borrow to Redbelly

`dstChainKey` and `dstAddress` default to the source, but any supported network can be the destination. That is the cross-network story in one parameter: collateral supplied from one network, borrowed liquidity delivered to another.

```typescript
const bnUSD = redbellyTokens.find(t => t.symbol === 'bnUSD');
if (!bnUSD) throw new Error('bnUSD is not a supported money-market token on Redbelly');

const result = await sodax.moneyMarket.borrow({
  params: {
    srcChainKey: ChainKeys.REDBELLY_MAINNET, // where the caller acts from
    srcAddress: userRedbellyAddress,
    token: bnUSD.address,                    // token on the destination network
    amount: 50n * 10n ** BigInt(bnUSD.decimals), // 50 bnUSD
    action: 'borrow',
    dstChainKey: ChainKeys.REDBELLY_MAINNET, // deliver on Redbelly
    dstAddress: userRedbellyAddress,
  },
  walletProvider,
});
```

Build every amount from the token's own `decimals`: on Redbelly, USDC and USDT use 6 while bnUSD uses 18.

`withdraw` and `repay` follow the same shape. Withdraw and borrow need no approval on any network; repaying with an ERC-20 token needs an allowance, like supply.

## Building a lending UI

`sodax.moneyMarket.data` exposes what you need for rates, positions, and health factors without extra indexing:

- `getReservesHumanized()`: all reserves, human-readable.
- `getUserReservesHumanized(spokeChainKey, userAddress)`: a user's positions.
- `formatReservesUSD(request)` / `formatUserSummary(request)`: USD-converted reserves and portfolio summaries.

## Error handling

The module returns typed results. Discriminate on `result.error.code` (`'RELAY_TIMEOUT'`, `'EXECUTION_FAILED'`, …) with structured context on `result.error.context`.
