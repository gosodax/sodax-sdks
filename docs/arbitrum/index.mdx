<Note>
  **No new contracts.** SODAX's Arbitrum spoke contracts are already live; your entire integration is TypeScript. Your users sign ordinary EVM transactions on Arbitrum One, and SODAX coordinates cross-network execution, routing, and recovery behind the scenes.
</Note>

You keep shipping on Arbitrum. SODAX absorbs the cross-network execution layer, so your product can offer trading and lending against every asset in the SODAX System, <span data-sodax-config="count" data-metric="swap-tokens">166</span> across all supported networks, without leaving your stack. Integration happens in TypeScript, at the SDK or React layer. There is nothing to deploy, audit, or maintain on-chain.

Using SODAX is free. Trades carry a fixed 0.1% base fee taken by the protocol, and you set your own platform fee on top. That part is fully yours, both the rate and the revenue. See [Monetize SDK](/developers/how-to/monetize_sdk).

## What to know on Arbitrum

Arbitrum works like any other EVM network in SODAX: the same `EvmWalletProvider`, the same ERC-20 approvals, and the same intent flow, with no Arbitrum-specific handling in the SDK. Gas is paid in ETH, which is also Arbitrum's native token in SODAX and needs no approval. If you already integrate SODAX on another EVM network, the only change is the chain key, `ChainKeys.ARBITRUM_MAINNET`.

## Scope and build with AI

Point your AI coding assistant at the [SODAX Builders MCP](/builders-mcp) and it gains live access to the whole SODAX System: supported chains and tokens, real swap quotes, money market rates, intent history, and these docs. It works in Claude, Cursor, VS Code, Windsurf, and any other MCP-capable client.

```json
{
  "mcpServers": {
    "sodax-builders": {
      "url": "https://builders.sodax.com/mcp"
    }
  }
}
```

Use it to scope before you commit: your assistant can read your own codebase, pull real quotes and token lists, and map exactly where SODAX fits in your product. Full tool list and per-client setup at [builders.sodax.com](https://builders.sodax.com/).
