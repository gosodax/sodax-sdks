## Recipe set shape

Every ecosystem ships the same three recipes, each a goal-driven, end-to-end scenario a
builder on that network would actually ship. They do not duplicate the reference pages
(`/<NETWORK_SLUG>/swaps`, `/<NETWORK_SLUG>/money-market`); they compose them into a result.

1. **Accept any token, settle on <NETWORK_TITLE>.** A user pays from the token and network
   they already hold; the app receives a <NETWORK_TITLE> asset (`<SETTLE_TOKEN>`) at an
   address it controls. One cross-network swap: `dstChainKey` = `<CHAIN_KEY>`.
2. **Use <NETWORK_TITLE> as a lending spoke.** Supply collateral from <NETWORK_TITLE> and
   borrow liquidity delivered to <PEER_NETWORK>, or borrow into <NETWORK_TITLE> against
   collateral held elsewhere. `srcChainKey` = `<CHAIN_KEY>`; `dstChainKey` sets delivery.
3. **Show balances across networks in a <NETWORK_TITLE> app.** Read the user's own balances
   across every connected network with `getWalletBalances` / `useBalances`, present them,
   then route a chosen holding into a <NETWORK_TITLE> asset via recipe 1.

## Page shape (each recipe)

- Frontmatter: `title`, `sidebarTitle`, `description`, `icon` (reuse the concept's icon:
  swaps `rotate`, money market `sack-dollar`, balances `wallet`).
- Opening paragraph: the goal in the network's own vocabulary.
- `## What you will build`
- `## Prerequisites` (SDK packages, a funded wallet with `<NATIVE_GAS_TOKEN>` for gas,
  server-side API key, mainnet-only caveat).
- `## Steps` with `<Steps>` / `<Step>`, each carrying working TypeScript.
- `## Error handling` (Result discrimination, the real failure modes).
- `## Next steps` linking into `/<NETWORK_SLUG>/...` guides and the SDK reference.
