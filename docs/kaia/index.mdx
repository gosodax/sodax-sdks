<Note>
  **No new contracts.** SODAX's Kaia spoke contracts are already live; your entire integration is TypeScript. Your users sign ordinary EVM transactions on Kaia, and SODAX coordinates cross-network execution, routing, and recovery behind the scenes.
</Note>

You keep shipping on Kaia. SODAX absorbs the cross-network execution layer, so your product can offer trading and lending against every asset in the SODAX System, <span data-sodax-config="count" data-metric="swap-tokens">166</span> across all supported networks, without leaving your stack. Integration happens in TypeScript, at the SDK or React layer. There is nothing to deploy, audit, or maintain on-chain.

Using SODAX is free. Trades carry a fixed 0.1% base fee taken by the protocol, and you set your own platform fee on top. That part is fully yours, both the rate and the revenue. See [Monetize SDK](/developers/how-to/monetize_sdk).

## What to know on Kaia

To the SDK, Kaia is a standard EVM network: the same `EvmWalletProvider`, ERC-20 approvals, and intent flow as any other EVM network. Two Kaia details are yours to know about:

- **The signing account must have a legacy account key.** Kaia lets an account change its key or switch to multisig and role-based keys. Ethereum-format transactions, which SODAX and EVM wallets send, only work from accounts with the `AccountKeyLegacy` type, whose address is derived from their key. Kaia creates new accounts with that type; an account whose key has been updated cannot sign SODAX transactions.
- **The public endpoint is for testing.** The SODAX config uses `https://public-en.node.kaia.io`, which Kaia provides for testing and development and asks not to be used commercially. Pass your own endpoint through `rpcUrl` in production.

## Scope and build with AI

Point your AI coding assistant at the [SODAX Builders MCP](/builders-mcp) and it gains live access to the whole SODAX System: supported chains and tokens, real swap quotes, money market rates, intent history, and these docs. It works in Claude, Cursor, VS Code, Windsurf, and any other MCP-capable client.

```json
{
  "mcpServers": {
    "sodax-builders": {
      "url": "https://builders.sodax.com/mcp"
    }
  }
}
```

Use it to scope before you commit: your assistant can read your own codebase, pull real quotes and token lists, and map exactly where SODAX fits in your product. Full tool list and per-client setup at [builders.sodax.com](https://builders.sodax.com/).
