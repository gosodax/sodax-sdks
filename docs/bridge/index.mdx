Low-level transfer primitives for when you need asset movement without swap logic: spoke → hub, hub → spoke, and spoke → spoke.

Start with the HTTP API at `https://api.sodax.com/v1/bridge`: list tokens, check allowance and approve, build the bridge intent, sign and broadcast it on the source network, then hand it to `submit-tx` and poll its status. The route list lives in the [`@sodax/bridge-api` client](https://github.com/gosodax/sodax-sdks/blob/main/packages/bridge-api/src/client.ts), and [`BRIDGE_API.md`](https://github.com/gosodax/sodax-sdks/blob/main/packages/sdk/docs/BRIDGE_API.md) covers each call's request and response types. Send your [API key](/developers/how-to/api-keys) as `x-api-key` from your server.

For a TypeScript flow, follow the [bridge usage flow](/developers/packages/foundation/sdk/functional-modules/bridge#usage-flow), then use the [bridge example](/developers/packages/foundation/sdk/functional-modules/bridge#bridge) to submit a transfer.
Check [completion and timeouts](/developers/packages/foundation/sdk/functional-modules/bridge#completion-paths-and-timeout) and [errors](/developers/packages/foundation/sdk/functional-modules/bridge#error-handling) before adding retries.
