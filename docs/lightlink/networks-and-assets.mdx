LightLink is a spoke network in the SODAX System. User funds stay on LightLink; the hub (Sonic) coordinates execution, and solvers settle against deep native liquidity on each network rather than isolated bridge pools.

There are two asset lists to keep straight, and the difference is the point of SODAX:

- **Assets on LightLink**: the <span data-sodax-config="count" data-metric="chain-swap-tokens" data-chain="lightlink">14</span> assets that live on LightLink itself, ETH and ERC-20 tokens. These are what your users hold, send, and receive on LightLink; the entry and exit points of any LightLink-side flow.
- **Assets across the SODAX System**: <span data-sodax-config="count" data-metric="swap-tokens">166</span> assets across all supported networks. Every one of them is a valid swap destination or collateral source for your LightLink users, because every SODAX action is cross-network by default.

A user holding ETH on LightLink is not limited to the LightLink-side list. They can swap it into ETH on Ethereum, USDC on Base, SOL on Solana, or any other listed asset on any network, in one signed transaction. The on-LightLink assets are simply where those journeys start and end on your side.

Every count and list below is read live from the backend config API, `GET https://api.sodax.com/v2/be/config/all`, so it reflects what the backend serves today rather than what an SDK release has listed.

## Assets on LightLink

Live for swaps on LightLink:

<div data-sodax-config="swap-tokens" data-chain="lightlink">
  Live token list loads from the config API. If it has not appeared, read `config.swaps.supportedTokens.lightlink` from [`GET /v2/be/config/all`](https://api.sodax.com/v2/be/config/all), or use the SDK call below.
</div>

Live in the [Money Market](/lightlink/money-market) for supply, borrow, repay, and withdraw:

<div data-sodax-config="money-market-tokens" data-chain="lightlink">
  Live token list loads from the config API: `config.moneyMarket.supportedTokens.lightlink` in [`GET /v2/be/config/all`](https://api.sodax.com/v2/be/config/all).
</div>

The two lists overlap but neither contains the other: the money market list includes tokens that are not in the swap list. Check each list for the action you are building.

Each address in these lists is a LightLink contract address; ETH uses the zero address. The `.LL` tokens are LightLink versions of assets native to other networks (BTC.LL is Bitcoin LightLink, SOL.LL is Solana LightLink, and so on). In the SODAX config each one maps to the same hub vault as the asset on its home network, and each uses 18 decimals. Look any address up on the [Phoenix explorer](https://phoenix.lightlink.io/).

Hub vault addresses per asset are listed in [Swaps: Compatible Assets](/developers/deployments/swaps-compatible-assets).

## Assets your users can reach

From a LightLink-sourced action, users can trade, lend, and borrow across every SODAX-supported network:

<div data-sodax-config="chains">
  Live network list loads from the config API: `config.chains` in [`GET /v2/be/config/all`](https://api.sodax.com/v2/be/config/all).
</div>

Chain identifiers come from `ChainKeys.*` in the SDK (`ChainKeys.LIGHTLINK_MAINNET` = `'lightlink'`), and the live chain list from `sodax.config.getSupportedSpokeChains()`. Prefer the config call over hard-coding: networks are added over time.

## Asset discovery in code

Never hard-code token addresses or asset lists; read them from the SDK config at runtime:

```typescript
import { Sodax, ChainKeys } from '@sodax/sdk';

const sodax = new Sodax();

// Swappable assets on LightLink
const swapTokens = sodax.swaps.getSupportedSwapTokensByChainId(ChainKeys.LIGHTLINK_MAINNET);

// Money market assets on LightLink
const mmTokens = sodax.moneyMarket.getSupportedTokensByChainId(ChainKeys.LIGHTLINK_MAINNET);
```

These lists ship with the SDK package, so a token the backend has added since your SDK release appears in the live tables above before it appears here.
