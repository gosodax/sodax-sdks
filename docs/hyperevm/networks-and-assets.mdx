HyperEVM is a spoke network in the SODAX System. User funds stay on HyperEVM; the hub (Sonic) coordinates execution, and solvers settle against deep native liquidity on each network rather than isolated bridge pools.

There are two asset lists to keep straight, and the difference is the point of SODAX:

- **Assets on HyperEVM**: the <span data-sodax-config="count" data-metric="chain-swap-tokens" data-chain="hyper">10</span> assets that live on HyperEVM itself, HYPE and ERC-20 tokens. These are what your users hold, send, and receive on HyperEVM; the entry and exit points of any HyperEVM-side flow.
- **Assets across the SODAX System**: <span data-sodax-config="count" data-metric="swap-tokens">166</span> assets across all supported networks. Every one of them is a valid swap destination or collateral source for your HyperEVM users, because every SODAX action is cross-network by default.

A user holding HYPE is not limited to the HyperEVM-side list. They can swap HYPE into ETH on Ethereum, USDC on Base, SOL on Solana, or any other listed asset on any network, in one signed transaction. The on-HyperEVM assets are simply where those journeys start and end on your side.

Every count and list below is read live from the backend config API, `GET https://api.sodax.com/v2/be/config/all`, so it reflects what the backend serves today rather than what an SDK release has listed.

Live in the [Money Market](/hyperevm/money-market) for supply, borrow, repay, and withdraw:

<div data-sodax-config="money-market-tokens" data-chain="hyper">

Each address in these lists is a HyperEVM contract address; HYPE uses the zero address. These are HyperEVM tokens only: a balance in HyperCore spot becomes usable once the user transfers it to HyperEVM, and only if the HyperEVM token is in the list. Look any address up on [HyperEVMScan](https://hyperevmscan.io/).

Hub vault addresses per asset are listed in [Swaps: Compatible Assets](/developers/deployments/swaps-compatible-assets).

## Assets your users can reach

From a HyperEVM-sourced action, users can trade, lend, and borrow across every SODAX-supported network:

<div data-sodax-config="chains">
  Live network list loads from the config API: `config.chains` in [`GET /v2/be/config/all`](https://api.sodax.com/v2/be/config/all).
</div>

Chain identifiers come from `ChainKeys.*` in the SDK (`ChainKeys.HYPEREVM_MAINNET` = `'hyper'`), and the live chain list from `sodax.config.getSupportedSpokeChains()`. Prefer the config call over hard-coding: networks are added over time.

## Asset discovery in code

Never hard-code token addresses or asset lists; read them from the SDK config at runtime:

```typescript
import { Sodax, ChainKeys } from '@sodax/sdk';

const sodax = new Sodax();

// Swappable assets on HyperEVM
const swapTokens = sodax.swaps.getSupportedSwapTokensByChainId(ChainKeys.HYPEREVM_MAINNET);

// Money market assets on HyperEVM
const mmTokens = sodax.moneyMarket.getSupportedTokensByChainId(ChainKeys.HYPEREVM_MAINNET);
```

These lists ship with the SDK package, so a token the backend has added since your SDK release appears in the live tables above before it appears here.
