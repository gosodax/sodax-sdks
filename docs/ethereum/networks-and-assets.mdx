Ethereum is a spoke network in the SODAX System. User funds stay on Ethereum; the hub (Sonic) coordinates execution, and solvers settle against deep native liquidity on each network rather than isolated bridge pools.

There are two asset lists to keep straight, and the difference is the point of SODAX:

- **Assets on Ethereum**: the <span data-sodax-config="count" data-metric="chain-swap-tokens" data-chain="ethereum">26</span> assets that live on Ethereum itself, ETH and ERC-20 tokens. These are what your users hold, send, and receive on Ethereum; the entry and exit points of any Ethereum-side flow.
- **Assets across the SODAX System**: <span data-sodax-config="count" data-metric="swap-tokens">166</span> assets across all supported networks. Every one of them is a valid swap destination or collateral source for your Ethereum users, because every SODAX action is cross-network by default.

A user holding ETH on Ethereum is not limited to the Ethereum-side list. They can swap it into USDC on Base, SOL on Solana, or any other listed asset on any network, in one signed transaction. The on-Ethereum assets are simply where those journeys start and end on your side.

Every count and list below is read live from the backend config API, `GET https://api.sodax.com/v2/be/config/all`, so it reflects what the backend serves today rather than what an SDK release has listed.

## Assets your users can reach

From an Ethereum-sourced action, users can trade, lend, and borrow across every SODAX-supported network:

<div data-sodax-config="chains">
  Live network list loads from the config API: `config.chains` in [`GET /v2/be/config/all`](https://api.sodax.com/v2/be/config/all).
</div>

Chain identifiers come from `ChainKeys.*` in the SDK (`ChainKeys.ETHEREUM_MAINNET` = `'ethereum'`), and the live chain list from `sodax.config.getSupportedSpokeChains()`. Prefer the config call over hard-coding: networks are added over time.

## Asset discovery in code

Never hard-code token addresses or asset lists; read them from the SDK config at runtime:

```typescript
import { Sodax, ChainKeys } from '@sodax/sdk';

const sodax = new Sodax();

// Swappable assets on Ethereum
const swapTokens = sodax.swaps.getSupportedSwapTokensByChainId(ChainKeys.ETHEREUM_MAINNET);

// Money market assets on Ethereum
const mmTokens = sodax.moneyMarket.getSupportedTokensByChainId(ChainKeys.ETHEREUM_MAINNET);
```

These lists ship with the SDK package, so a token the backend has added since your SDK release appears in the live tables above before it appears here.
