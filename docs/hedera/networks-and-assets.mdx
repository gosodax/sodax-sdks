Hedera is a spoke network in the SODAX System. User funds stay on Hedera; the hub (Sonic) coordinates execution, and solvers settle against deep native liquidity on each network rather than isolated bridge pools.

There are two asset lists to keep straight, and the difference is the point of SODAX:

- **Assets on Hedera**: the <span data-sodax-config="count" data-metric="chain-swap-tokens" data-chain="hedera">40</span> assets that live on Hedera itself, HBAR and HTS tokens. These are what your users hold, send, and receive on Hedera; the entry and exit points of any Hedera-side flow.
- **Assets across the SODAX System**: <span data-sodax-config="count" data-metric="swap-tokens">166</span> assets across all supported networks. Every one of them is a valid swap destination or collateral source for your Hedera users, because every SODAX action is cross-network by default.

A user holding HBAR is not limited to the Hedera-side list. They can swap HBAR into ETH on Ethereum, USDC on Base, SOL on Solana, or any other listed asset on any network, in one signed transaction. The on-Hedera assets are simply where those journeys start and end on your side.

Every count and list below is read live from the backend config API, `GET https://api.sodax.com/v2/be/config/all`, so it reflects what the backend serves today rather than what an SDK release has listed.

Live in the [Money Market](/hedera/money-market) for supply, borrow, repay, and withdraw:

<div data-sodax-config="money-market-tokens" data-chain="hedera">
  Live token list loads from the config API: `config.moneyMarket.supportedTokens.hedera` in [`GET /v2/be/config/all`](https://api.sodax.com/v2/be/config/all).

Each address in these lists is the EVM form of a Hedera token ID: the token ID's number, zero-padded to 20 bytes. USDC, token `0.0.456858`, is `0x000000000000000000000000000000000006f89a`. HBAR uses the zero address. To look a token up on [HashScan](https://hashscan.io/) or the mirror node, convert the address back to its token ID: `0.0.${BigInt(address)}`.

Hub vault addresses per asset are listed in [Swaps: Compatible Assets](/developers/deployments/swaps-compatible-assets).

## Assets your users can reach

From a Hedera-sourced action, users can trade, lend, and borrow across every SODAX-supported network:

<div data-sodax-config="chains">
  Live network list loads from the config API: `config.chains` in [`GET /v2/be/config/all`](https://api.sodax.com/v2/be/config/all).
</div>

Chain identifiers come from `ChainKeys.*` in the SDK (`ChainKeys.HEDERA_MAINNET` = `'hedera'`), and the live chain list from `sodax.config.getSupportedSpokeChains()`. Prefer the config call over hard-coding: networks are added over time.

## Asset discovery in code

Never hard-code token addresses or asset lists; read them from the SDK config at runtime:

```typescript
import { Sodax, ChainKeys } from '@sodax/sdk';

const sodax = new Sodax();

// Swappable assets on Hedera
const swapTokens = sodax.swaps.getSupportedSwapTokensByChainId(ChainKeys.HEDERA_MAINNET);

// Money market assets on Hedera
const mmTokens = sodax.moneyMarket.getSupportedTokensByChainId(ChainKeys.HEDERA_MAINNET);
```

These lists ship with the SDK package, so a token the backend has added since your SDK release appears in the live tables above before it appears here.
