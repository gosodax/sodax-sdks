Fragmented money markets mean lower capital efficiency and worse rates. The SODAX money market pools lending liquidity on the hub while letting users act from any supported network, including Hedera. A user can supply HTS tokens from Hedera and borrow on another network, or borrow into their Hedera account against collateral held elsewhere, without your product running its own lending infrastructure.

Four actions, all through `sodax.moneyMarket`: `supply`, `borrow`, `withdraw`, `repay`. Each has a complete one-call form (handles the relay end-to-end) and a `create*Intent` form when you want the transaction only.

The assets that work in the money market from Hedera are a subset of the Hedera swap list, and native HBAR is not among them today. Read the list at runtime, as below, or see [Networks & Assets](/hedera/networks-and-assets).

## Supply from Hedera

Supplying an HTS token needs an ERC-20 allowance first, the same as any EVM network:

```typescript
import { Sodax, ChainKeys } from '@sodax/sdk';

const sodax = new Sodax();

// find() returns XToken | undefined, so narrow before using the address
const hederaTokens = sodax.moneyMarket.getSupportedTokensByChainId(ChainKeys.HEDERA_MAINNET);
const usdc = hederaTokens.find(t => t.symbol === 'USDC');
if (!usdc) throw new Error('USDC is not a supported money-market token on Hedera');

const params = {
  srcChainKey: ChainKeys.HEDERA_MAINNET,
  srcAddress: await walletProvider.getWalletAddress(),
  token: usdc.address,
  amount: 100n * 10n ** BigInt(usdc.decimals), // 100 USDC
  action: 'supply',
} as const;

const allowance = await sodax.moneyMarket.isAllowanceValid({ params });
if (!allowance.ok) throw allowance.error;
if (!allowance.value) {
  const approval = await sodax.moneyMarket.approve({ params, walletProvider });
  if (!approval.ok) throw approval.error;
  // wait for the approval to be mined before supplying
}

const result = await sodax.moneyMarket.supply({
  params,
  walletProvider, // IEvmWalletProvider, narrowed by srcChainKey
  timeout: 120_000, // optional relay timeout (default 120 s)
});
```

## Borrow to Hedera

`dstChainKey` and `dstAddress` default to the source, but any supported network can be the destination. That is the cross-network story in one parameter: collateral supplied from one network, borrowed liquidity delivered to another.

```typescript
const bnUSD = hederaTokens.find(t => t.symbol === 'bnUSD');
if (!bnUSD) throw new Error('bnUSD is not a supported money-market token on Hedera');

const result = await sodax.moneyMarket.borrow({
  params: {
    srcChainKey: ChainKeys.HEDERA_MAINNET,  // where the caller acts from
    srcAddress: userHederaAddress,
    token: bnUSD.address,                    // token on the destination network
    amount: 50n * 10n ** BigInt(bnUSD.decimals), // 50 bnUSD
    action: 'borrow',
    dstChainKey: ChainKeys.HEDERA_MAINNET,   // deliver on Hedera
    dstAddress: userHederaAddress,
  },
  walletProvider,
});
```

Build every amount from the token's own `decimals`: on Hedera most HTS tokens in the SODAX list use 8, and USDC uses 6.

When Hedera is the destination of a borrow or a withdraw, the receiving account must be able to receive that HTS token. Check it with the mirror node before you submit: [Receiving tokens on Hedera](/hedera/swaps#receiving-tokens-on-hedera).

`withdraw` and `repay` follow the same shape. Withdraw and borrow need no approval on any network; repaying with an HTS token needs an allowance, like supply.

## Building a lending UI

`sodax.moneyMarket.data` exposes what you need for rates, positions, and health factors without extra indexing:

- `getReservesHumanized()`: all reserves, human-readable.
- `getUserReservesHumanized(spokeChainKey, userAddress)`: a user's positions.
- `formatReservesUSD(request)` / `formatUserSummary(request)`: USD-converted reserves and portfolio summaries.

## Error handling

The module returns typed results. Discriminate on `result.error.code` (`'RELAY_TIMEOUT'`, `'EXECUTION_FAILED'`, …) with structured context on `result.error.context`.
